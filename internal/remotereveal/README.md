# Unmounted reveal executor

No HTTP route or authentication integration is provided. A future integration must use enabled auth middleware on a state-changing, CSRF-checked interactive confirmation request, require `auth.CookieAuthenticated`, obtain the trusted `auth.Identity`, acquire `auth.SubmissionLease`, and pass its context and release function exactly once to `Execute`. A caller-provided Submission is a trust boundary, not evidence of authentication. The caller must not release it early or reuse it. Logout waits for a held submission; cancellation or session expiry denies subsequent work, but cannot recall network requests or bytes already written.

The caller must provide the exact record and full container ID shown at confirmation, and a protected, synchronous, cancellation-aware Ed25519 signer. The grant SessionID is a fresh random grant identifier, not an agent-verifiable user identity or a cryptographic binding to an authenticated user session. Admin attribution relies on the trusted external session and the audit record. The opener is privileged injection: production must use `PinnedOpener`, and test openers must provide equivalent response validation. The signer, opener, audit and delivery callbacks must not log or retain secrets, grants, or raw errors. Do not start detached work. Delivery is synchronous under both leases; delivery code must honor its context, avoid partial responses, and not retain values. The executor cannot retract bytes already delivered or enforce behavior inside injected components. No stream is returned.

A failed/canceled audit operation may leave a pending or uncertain journal entry; reconcile via revealaudit rather than retrying blindly. The recorded success means the reveal was obtained and durably audited, not that response delivery succeeded. Registry leases coordinate only cooperating registry writers; direct edits bypass them. `ErrCleanup` is a sanitized signal that resource release failed; no underlying error details are exposed. A read-lease close error may only become known after delivery and cannot retract delivered bytes. This package does not protect key storage or establish trusted confirmation, and is not ready to mount without separate review of those integrations and delivery semantics.
