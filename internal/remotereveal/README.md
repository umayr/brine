# Reveal executor

The optional HTTP integration uses enabled auth middleware on a state-changing, CSRF-checked interactive confirmation request, requires `auth.CookieAuthenticated`, obtains the trusted `auth.Identity`, atomically consumes a one-shot confirmation bound to the same cookie session, acquires the real revocable `auth.SessionContext`, and passes its context and cancel function exactly once to `Execute`. Any other integration must preserve these requirements. A caller-provided Submission is a trust boundary, not evidence of authentication. The caller must not release it early or reuse it. Logout or session expiry cancels the context, but cannot recall network requests or bytes already written; checks and network operations are not atomic with revocation.

The caller must provide the exact record, full container ID, and request ID bound at confirmation, and a protected, synchronous, cancellation-aware Ed25519 signer. The request ID must be generated before confirmation and retained with that one-shot approval; the executor puts it unchanged into the signed grant. The grant SessionID is a fresh random grant identifier, not an agent-verifiable user identity or a cryptographic binding to an authenticated user session. Admin attribution relies on the trusted external session and the audit record. The opener is privileged injection: production must use `PinnedOpener`, and test openers must provide equivalent response validation. The signer, opener, audit and delivery callbacks must not log or retain secrets, grants, or raw errors. Do not start detached work. Delivery is synchronous under both leases; delivery code must honor its context, avoid partial responses, and not retain values. The executor cannot retract bytes already delivered or enforce behavior inside injected components. No stream is returned.

## Operator provisioning

Provision a private signing key separately; `remoteui.OpenRevealHandler` loads it with `revealsigner.Open` and does not generate a key. The lower-level `OpenConfigured` takes the already-open signer. Use exactly 32 seed bytes encoded as 64 lowercase hexadecimal characters, optionally followed by one LF. See `internal/revealsigner/README.md`: trusted ancestors and effective ACLs are operator responsibilities, concurrent writers must be excluded, and the loaded key remains in process memory. Initialize the audit journal explicitly in an existing private 0700 directory using `brine-reveal-audit-init DIRECTORY`. Never rerun initialization after an uncertain result without manual reconciliation. `OpenConfigured` uses `revealaudit.Open` and rejects missing or damaged established state; it never initializes it. Read the package documentation in `internal/revealaudit/audit.go` before provisioning. The audit root, all ancestors, mount and cooperating writers must be trusted against replacement or modification. Mode checks do not establish that ACLs are safe: operators must independently prevent access through ACLs. The filesystem must honor locking, append, file and directory fsync and close semantics; sync errors may leave an uncertain persisted state. Root deletion cannot be distinguished from a new empty root without an external inventory or anchor. Do not use network filesystems lacking these guarantees. Protect the signing key and its ancestors and ACLs independently.

`remoteui.NewRevealHandler` is a separate unmounted handler. The production dispatcher mounts only its two exact routes when explicitly configured; unconfigured read routes remain unaffected. Its process-local approval is bound to the current authenticated cookie without displaying that credential; the exact registry record, full container ID and v2 request ID are shown and retained for one use. Logout and expiry cancel the work, subject to scheduling and the inability to recall requests or bytes already sent. UI value clearing is best effort: browser suspension, timers, clock changes, network and buffered bytes prevent guaranteed immediate removal or erasure. Both monotonic and wall-clock elapsed deadlines are checked when JavaScript runs, but neither can enforce clearing while the browser is suspended. Other metadata and logs can also contain secrets. Production wiring and deployment configuration require independent review.

A failed/canceled audit operation may leave a pending or uncertain journal entry; reconcile via revealaudit rather than retrying blindly. The recorded success means the reveal was obtained and durably audited, not that response delivery succeeded. Registry leases coordinate only cooperating registry writers; direct edits bypass them. `ErrCleanup` is a sanitized signal that resource release failed; no underlying error details are exposed. A read-lease close error may only become known after delivery and cannot retract delivered bytes. This package does not protect key storage or establish trusted confirmation, and requires separate review of integrations and delivery semantics.
