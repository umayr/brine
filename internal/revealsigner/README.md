# Reveal signer

`Open(path)` loads an existing operator-provisioned Ed25519 seed and returns a `*Signer` implementing `remotereveal.Signer`. Provision exactly 32 seed bytes encoded as 64 lowercase hexadecimal characters, optionally followed by one LF. No key is generated or persisted by this package. Errors intentionally omit the path, contents and underlying OS error.

The path must be absolute, clean and non-root. On Linux and macOS, the final component must be an existing regular file owned by the effective UID, with exactly mode 0600 (including no special mode bits); it is opened with `O_NOFOLLOW` and checked through the descriptor. Reads are bounded; checks for changes or replacement during loading are best effort and do not provide a stable snapshot. Other platforms fail closed. `PublicKey` returns a copy; `Sign` checks context before and after synchronous Ed25519 signing, but cannot interrupt the signing operation.

**Operator trust requirements:** Place the key under a private root and trusted ancestors. Ancestor ownership, permissions and symlinks are not enforced here, and effective ACL controls are not checked; secure these separately. Exclude concurrent writers and path controllers operationally: anyone able to modify the file or control its path, including same-UID and ACL-authorized actors, can defeat the checks. Protect backups as private key material. The loaded key remains in process memory for the process lifetime; no secure erasure is promised. Changes to the file after loading are not noticed: restart to load a new key and coordinate rotation with every verifier's trust configuration. Restoring a backup or restarting with a different key changes signing identity and may break or alter trust; never silently replace a missing key.
