# Target enrollment registry

This package stores reviewed public enrollment data; it performs no network discovery, authentication, UI, or secret-key storage. The caller must independently authenticate observations and display **all** fields of both old and new records to the operator, including host, port, user, key path and every identity field. The UI must issue and consume a protected one-shot approval token bound to the exact displayed values; this package does not implement that token or prove human approval. Retain the exact reviewed value and pass it to `Add(candidate, reviewed)` or `Update(expectedPrevious, candidate, ReviewedUpdate{Previous: reviewedOld, Next: reviewedNew})`. A boolean is not approval. The caller must not construct reviewed values from changed candidates after approval. Updates are locked compare-and-swap against the complete previous record, require the same ID and an incremented revision, and fail for unknown IDs. New records start at revision 1. Revision prevents ABA while registry history is retained; rollback of the whole directory is outside this guarantee. `Verify` compares a complete observed record including configuration and revision. `Binding` returns a fresh agentclient binding with a separately allocated public-key slice.

AgentPublicKey is canonical unpadded base64url Ed25519 public key; AgentInstallationID is lowercase hexadecimal SHA-256 of those bytes and AgentFingerprint is `SHA256:` plus unpadded standard base64 of the same digest. HostPublicKey is the exact canonical OpenSSH public key and its SHA-256 pin must match. RevealKeyFingerprint is the same SHA-256 fingerprint format over the raw Ed25519 public key, independently obtained for the reveal verification public key. Before supplying a reveal key to agentclient, call `VerifiedRevealKey` and use its returned copy; a mismatched or unavailable key fails closed. The registry does not authenticate the original observation. EngineID is the canonical lowercase UUID, Generation is the positive protocol uint64, EngineSocket is a clean absolute `unix://` URL, and RemoteSocket is a clean absolute Unix path. Exact comparison is case sensitive; no hostname or ID case folding is performed. All review-sensitive strings are restricted to printable ASCII (bytes 0x20 through 0x7e), preventing invisible Unicode distinctions; individual fields impose additional restrictions. Non-ASCII paths and identifiers are intentionally unsupported. Values are bounded and validated, and records contain only immutable strings and integers.

For a remote operation, call `AcquireRead(ctx, id)` and use its returned validated value exclusively; retain the lease until the operation **and its stream** have completely terminated, then call `Close`. Cancellation of the acquisition context after return does not close the lease: cancel/terminate the operation and close it explicitly. `Close` is safe to repeat. Writers, including legacy `Add` and `Update`, wait for all leases and can therefore block for the entire stream duration. Use `AddContext`/`UpdateContext` to bound lock waits; these contexts do not interrupt a write after the lock is acquired. `AcquireRead` requires the existing lock file and fails closed if it is missing, malformed, or the record is missing or malformed. All cooperating processes must use this protocol; never unlink or replace `.lock`. Kernel locks are released on process exit.

The root and its ancestors must be controlled by the operator, private from untrusted writers, stable (not renamed or replaced), and shared under the same canonical path by cooperating processes. The filesystem must provide working cross-process `flock`, stable lock-file inode identity, atomic same-directory rename, and supported file and directory sync semantics; do not assume network or unusual filesystems provide these guarantees. Advisory locking only coordinates callers of this API. A malicious same-user process, hostile filesystem, directory rollback, or replacement of files outside the API is not protected. Writes use a private temporary file, sync, atomic rename and directory sync. Context-aware writes check cancellation immediately before mutation and before rename, but cancellation can race the OS rename and cannot undo publication; an error or expired context after that boundary may mean the new value was installed. Reconcile by reloading before deciding what to do; do not blindly retry. Unknown versions, malformed, noncanonical, duplicate, or insecure files fail closed and are never automatically repaired or migrated. Version 1 is deliberately rejected: it lacks the complete binding and must be re-enrolled out of band.
