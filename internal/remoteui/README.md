# Remote host UI

The server mounts this package only when explicitly configured, using the pinned remote transport and strict existing registry. `ProtectedRoutes` combines the read and enrollment handlers and optionally the reviewed reveal handler using the same enabled authenticator; it denies the legacy `/remote/reveal` path; it is mounted outside the server's global authentication middleware so the body limit runs before authentication form parsing and authentication is not applied twice. Never mount the raw handler or put form-parsing middleware ahead of `Protected()`. Each wrapper bounds the body **before** the same authenticator's CSRF middleware and applies no-store to its errors. Remote reads require a cookie session and use a context cancelled on logout or session expiry; stream callbacks and later writes stop on cancellation. Cancellation cannot recall an in-progress write or bytes already buffered by the server, network, or browser, and logout cancellation is subject to goroutine scheduling. `New` rejects no-auth mode. The reveal review response sets its own restrictive nonce-based CSP and denies framing; deployment middleware must not replace it with a weaker policy. Restrict access to the authenticated administrator. Reveal is disabled unless explicitly configured; when enabled, only the dedicated review and approval endpoints are mounted. `OpenRevealHandler` constructs the review/approval handler using an explicitly provisioned signer and previously initialized audit; see `internal/remotereveal/README.md`. Its confirmation is cookie-session-bound, one-use and retains the exact quoted record, container and request ID. Bearer and no-auth requests are explicitly rejected server-side for enrollment, logs and reveal.

Implement `Backend` in the transport/registry owner's integration layer, not here. It must provide the authoritative supervisor's `brine.agent.read/1` contract: strict pinned SSH host key and private Unix-socket forwarding, authenticated SSH, no legacy or mutating routes, session proof and enrolled binding/epoch checks, canonical signatures and independent agent-side validation. Recheck ownership and identity before each read and throughout streams, fail closed on changes or unsupported engine identity, enforce all protocol limits, and prevent redirects, fallback and reveal retries. The separate enrollment handler displays complete validated records and retains a session-bound one-shot old/new snapshot. Its observer must establish a fresh pinned connection and verify the candidate without adopting pins; approval re-observes and commits via exact registry CAS. The legacy `/remote/review` and `/remote/enroll` paths are disabled. Review state is process-local and is invalidated by restart; use sticky routing or a protected shared one-shot store if deploying multiple instances. Inspect, logs and reveal require exactly 64 lowercase hexadecimal characters for the canonical full container ID before any backend call; inspected IDs must exactly match. This deliberately rejects engines with another identifier format until a separately defined engine-specific contract is implemented. `RegistryLeaseProvider` acquires the shared registry lease before opening a pinned agent session and releases it only after the request has rendered or streamed and the session is closed. Cleanup errors are returned and recorded as a fixed, identifier-free server message; errors discovered after delivery cannot undo delivered bytes. This relies on cooperating registry writers and the filesystem assumptions in the registry README. The dispatcher requires write-deadline support for reads, interrupting blocked writes on session cancellation; inventory and inspect have a 30-second request lifetime including response writes. Small responses are explicitly flushed while the registry lease and write deadline remain active. Flush errors are logged as fixed, identifier-free messages and the connection retains an expired write deadline; delivery can be incomplete. Bytes already accepted by the network or buffered by clients cannot be recalled. The backend remains responsible for live Dill ownership and exact immutable engine IDs; `Inventory` must not silently present a truncated page as complete. `Inspect` returns the full v1 normalized `Inspection` profile, including `ObservedAt`, image identity, nullable scalar fields (pointers), ports, mounts, networks, health, resources, security, and the three Dill ownership labels. Map the contract's `containerId` and `inspect.id` to the same canonical `Inspection.ID` after validating equality; arrays and labels must follow the contract's bounds and allowlist. `Inspect` returns environment **names only**, never values or raw inspect data. Other metadata and logs may contain secrets.

`Logs` returns a `LogStream` of validated decoded chunks, heartbeats and authentic end reasons. Its adapter must validate agent envelopes, sequence numbers, termination, encoded sizes, ownership/binding rechecks, backpressure and concurrency; `Next` must unblock on context cancellation and `Close` must cancel engine reads. Never manufacture an end event after EOF or error. The handler adds 16 KiB chunk, 1 MiB decoded, 2 MiB wire, 4096-event and token-bucket (256 burst, 200/s) caps; repeated heartbeats within 20 seconds fail closed. Tail/follow deadlines are 15 seconds/five minutes, including final response flush on both success and error paths. These UI caps may terminate a valid agent stream with many tiny chunks; termination is reported as truncation. It reports agent end reasons and local truncation, invalid data, errors or missing end distinctly via browser NDJSON. The adapter is responsible for differentiating valid agent error frames from valid end frames and must never fabricate completion. `Reveal` must sign a fresh short-lived per-container grant only after foreground confirmation, rely on agent-side signature and replay validation, and never retry. Neither grant nor values may enter logs, telemetry, persistent storage, browser storage or audit. `BeginRevealAudit` must synchronously persist a durable intent before returning an opaque correlation ID; failure denies signing. `FinishRevealAudit` separately persists outcome without grants or values, and failure denies delivery, but cannot undo an agent access already made. An intent may remain without an outcome after crash, cancellation or audit failure and must be monitored/reconciled; outcome success means backend returned valid-sized data while session was valid at that point, not that a browser received it. The executor attempts Finish within the revocable request context; cancellation can leave a pending intent. `Audit` for other reads is currently best-effort and cannot report failure. Protect the handler and backend from logging HTTP bodies. Reveal requests have a 30-second request context and an absolute response write deadline retained through HTTP final framing, including failures; blocked OS filesystem operations may outlive context cancellation. Logout races remain best effort, and already-buffered bytes cannot be recalled. The reveal UI has no native submission fallback when JavaScript is disabled or blocked. Values clear on page hide, explicit clear, at the server-reported expiry (with a one-second conservative margin), after 30 seconds, or when the session status endpoint is denied/unreachable. While displayed, status is revalidated every two seconds; external logout or server-side revocation may therefore remain visible until the next check, and browser suspension, timer throttling, network delay or an unresponsive browser prevent a guarantee of immediate clearing. The client refuses to display a reveal until a fresh status check succeeds. This is best-effort UI clearing, not proof of disconnect, browser closure, memory erasure or human presence.

Before production integration add real SSH/agent and signature fixtures, re-enrollment/race/replay tests, session-revocation push or equivalent if stricter clearing is required, endpoint status and pagination UX, inaccessible-engine handling, and end-to-end browser tests against the actual auth and backend. Enrollment uses a pinned observer and target registry. No deployment, remote action or staging endpoint is added.
