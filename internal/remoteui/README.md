# Remote host UI integration seam (not enabled)

This package is an opt-in skeleton, not a remote client or agent implementation. Nothing mounts it in the production router. Pass the enabled authenticator to `New` and mount its `Protected()` handler on `/remote` and `/remote/*`; never mount the raw handler or put form-parsing middleware ahead of `Protected()`. This wrapper bounds the body **before** the same authenticator's CSRF middleware and applies no-store to its errors. `New` rejects no-auth mode. Ensure the deployment's CSP permits the page script, or move it to an allowed static asset. Restrict access to the authenticated administrator. The UI uses a checkbox and CSRF-protected per-container POST. Immediately before calling `Reveal`, the handler acquires `SubmissionLease`, revalidating the cookie and serializing against logout; its context deadline is session expiry. The adapter must check the context immediately before signing and promptly sign/send within that lease, abort on cancellation, never queue signing, and never retry. Logout waits for an acquired lease; an already-started network request cannot be recalled. A browser request or checkbox cannot prove human presence or browser presence. Bearer and no-auth requests are explicitly rejected server-side for enrollment, logs and reveal.

Implement `Backend` in the transport/registry owner's integration layer, not here. It must provide the authoritative supervisor's `brine.agent.read/1` contract: strict pinned SSH host key and private Unix-socket forwarding, authenticated SSH, no legacy or mutating routes, session proof and enrolled binding/epoch checks, canonical signatures and independent agent-side validation. Recheck ownership and identity before each read and throughout streams, fail closed on changes or unsupported engine identity, enforce all protocol limits, and prevent redirects, fallback and reveal retries. `Review` returns the complete observed enrollment tuple; the UI rejects control/format/bidi characters, retains a bounded two-minute one-shot copy bound to the cookie session, and posts only an opaque random review token. `Enroll` must compare the retained reviewed tuple with a fresh verified observation and only pin it after the operator's out-of-band verification. Review state is process-local and is invalidated by restart; use sticky routing or a protected shared one-shot store if deploying multiple instances. Inspect, logs and reveal require exactly 64 lowercase hexadecimal characters for the canonical full container ID before any backend call; inspected IDs must exactly match. This deliberately rejects engines with another identifier format until a separately defined engine-specific contract is implemented. The backend remains responsible for live Dill ownership and exact immutable engine IDs; `Inventory` must not silently present a truncated page as complete. `Inspect` returns the full v1 normalized `Inspection` profile, including `ObservedAt`, image identity, nullable scalar fields (pointers), ports, mounts, networks, health, resources, security, and the three Dill ownership labels. Map the contract's `containerId` and `inspect.id` to the same canonical `Inspection.ID` after validating equality; arrays and labels must follow the contract's bounds and allowlist. `Inspect` returns environment **names only**, never values or raw inspect data. Other metadata and logs may contain secrets.

`Logs` returns a `LogStream` of validated decoded chunks, heartbeats and authentic end reasons. Its adapter must validate agent envelopes, sequence numbers, termination, encoded sizes, ownership/binding rechecks, backpressure and concurrency; `Next` must unblock on context cancellation and `Close` must cancel engine reads. Never manufacture an end event after EOF or error. The handler adds 16 KiB chunk, 1 MiB decoded, 2 MiB wire, 4096-event and token-bucket (256 burst, 200/s) caps; repeated heartbeats within 20 seconds fail closed. Tail/follow deadlines are 15 seconds/five minutes. These UI caps may terminate a valid agent stream with many tiny chunks; termination is reported as truncation. It reports agent end reasons and local truncation, invalid data, errors or missing end distinctly via browser NDJSON. The adapter is responsible for differentiating valid agent error frames from valid end frames and must never fabricate completion. `Reveal` must sign a fresh short-lived per-container grant only after foreground confirmation, rely on agent-side signature and replay validation, and never retry. Neither grant nor values may enter logs, telemetry, persistent storage, browser storage or audit. `BeginRevealAudit` must synchronously persist a durable intent before returning an opaque correlation ID; failure denies signing. `FinishRevealAudit` separately persists outcome without grants or values, and failure denies delivery, but cannot undo an agent access already made. An intent may remain without an outcome after crash, cancellation or audit failure and must be monitored/reconciled; outcome success means backend returned valid-sized data while session was valid at that point, not that a browser received it. Finish is attempted with an independent three-second context. `Audit` for other reads is currently best-effort and cannot report failure. Protect the handler and backend from logging HTTP bodies. The reveal UI has no native submission fallback when JavaScript is disabled or blocked. Values clear on page hide, explicit clear, at the server-reported expiry (with a one-second conservative margin), after 30 seconds, or when the session status endpoint is denied/unreachable. While displayed, status is revalidated every two seconds; external logout or server-side revocation may therefore remain visible until the next check, and browser suspension, timer throttling, network delay or an unresponsive browser prevent a guarantee of immediate clearing. The client refuses to display a reveal until a fresh status check succeeds. This is best-effort UI clearing, not proof of disconnect, browser closure, memory erasure or human presence.

Before production integration add real SSH/agent and signature fixtures, re-enrollment/race/replay tests, session-revocation push or equivalent if stricter clearing is required, endpoint status and pagination UX, inaccessible-engine handling, and end-to-end browser tests against the actual auth and backend. No target registry or transport is supplied here; no deployment, remote action or staging endpoint is added.
