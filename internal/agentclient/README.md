# Read-only agent client

This package is a client for the proposed v1 protocol, not the agent, an SSH implementation, an interactive user session, an authorization service or an audit system. The caller must own an authenticated, pinned SSH forwarding connection, create its private local Unix socket, and cancel the `forward` context immediately when that exact forward is lost or torn down. The caller is responsible for cleanup and for the independent out-of-band enrollment of the agent key, engine binding and reveal verification key. An SSH host key or socket path alone does not authenticate the agent.

`New`/`NewWithRevealKey` own one HTTP/1 connection only. `Session` proves identity on that connection; every subsequent request uses that same connection. No redial is permitted. Forward cancellation, connection loss or a non-200 response permanently invalidates the client and active epoch. Create a new forward and client and verify a new session proof to reconnect. Calls serialize on one connection, so a log stream prevents other calls until it ends; this is an intentional safety tradeoff. Call `Close` on teardown. Context cancellation and explicit teardown cancel active requests. The forward lifetime context is a trust boundary: failure to cancel it when the tunnel is lost violates this contract.

A reveal grant must be issued by an independently authorized upstream only after the required foreground confirmation. This client does not prove a user session, issue grants or perform auditing. Its local in-memory one-shot check is defense in depth and cannot replace the agent's independent signature/clock/ownership/replay enforcement, including restart and snapshot protections. The agent must enforce all engine binding, ownership and data-sanitization rules; this client cannot attest that it does.

Inspection commands/paths, log events and reveal values may contain secrets. Do not log, persist, cache or automatically resume them. `Logs` invokes its sink synchronously, with a context canceled at teardown and a five-second deadline per event. The sink **must cooperate** with that context and return promptly. The client waits for the sink before `Logs` returns; it cannot force an uncooperative callback to terminate, and therefore an uncooperative sink can block teardown indefinitely. There is no background callback that could deliver bytes after `Logs` returns. After a valid end frame, the client allows five seconds for EOF, rejects trailing frames and still honors caller cancellation; this grace is separate from the stream duration and heartbeat timers. A non-200 response retires the client immediately, while its bounded error body can still be read; caller cancellation, explicit `Close`, and forward loss interrupt that read.
