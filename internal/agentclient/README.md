# Read-only agent client

## Paired-process integration test

The request-bound reveal integration was verified with the supervisor-provided `/tmp/dill-agent-v2`. Its embedded Go build metadata reports Dill revision `917aa26d7d521f313a323f95c46f2db92f15b43f`, `vcs.modified=false`, and Go `1.27.3` on darwin/arm64; its SHA-256 was `d1ac9faf5b0b838014b53a8dfa5200d32d0dbbfc8bdc6c1f2701cf967f34ce98`. Metadata is not independent provenance attestation. The previously tested Dill revision `1e7ee21e913d73c15cf411e6c88bf5b21cf3ffeb` implements the old reveal protocol and is incompatible.

```sh
go version -m /tmp/dill-agent-v2
shasum -a 256 /tmp/dill-agent-v2
DILL_AGENT_BIN=/tmp/dill-agent-v2 go test ./internal/agentclient -run '^TestPairProcess$' -count=1 -v
DILL_AGENT_BIN=/tmp/dill-agent-v2 go test -race ./internal/agentclient -count=1
```

Inspect the printed binary metadata for the expected `vcs.revision` and `vcs.modified=false`; the test itself does not enforce provenance. Without `DILL_AGENT_BIN`, this test skips; a configured but unusable executable fails. It starts the real agent with a synthetic private Unix-socket HTTP engine and synthetic keys; it does not connect to Docker, Podman, or a remote machine. It uses local IPC, **not SSH**; real SSH forwarding, host-key pinning and remote deployment remain deferred and unverified. The agent socket is the caller-access boundary, not an authenticated user session. Mutation checks are narrow epoch-bearing probes of selected rejected routes, not proof of an authenticated connection or exhaustive mutation absence: the agent rejects those paths before checking the epoch. The sentinel checks cover only the literal synthetic fixture in the raw inspection response and bounded agent stdout/stderr; reveal intentionally returns it. Grant replay is checked both in the client and using a second client against the agent. The test also bypasses the client guard to check that the agent rejects a substituted request header for a different signed ID. Replay denial accepts either `UNAUTHORIZED` or `REPLAY`.

This package is a client for the proposed v1 protocol, not the agent, an SSH implementation, an interactive user session, an authorization service or an audit system. The caller must own an authenticated, pinned SSH forwarding connection, create its private local Unix socket, and cancel the `forward` context immediately when that exact forward is lost or torn down. The caller is responsible for cleanup and for the independent out-of-band enrollment of the agent key, engine binding and reveal verification key. An SSH host key or socket path alone does not authenticate the agent.

`New`/`NewWithRevealKey` own one HTTP/1 connection only. `Session` proves identity on that connection; every subsequent request uses that same connection. No redial is permitted. Forward cancellation, connection loss or a non-200 response permanently invalidates the client and active epoch. Create a new forward and client and verify a new session proof to reconnect. Calls serialize on one connection, so a log stream prevents other calls until it ends; this is an intentional safety tradeoff. Call `Close` on teardown. Context cancellation and explicit teardown cancel active requests. The forward lifetime context is a trust boundary: failure to cancel it when the tunnel is lost violates this contract.

A reveal grant must be issued by an independently authorized upstream only after the required foreground confirmation. The authorized caller generates `NewRequestID` before signing and supplies it as `Grant.RequestID`; it is 16 random bytes encoded as 32 lowercase hex characters. The v2 signature domain is `brine-agent-reveal/2\0`, with `LP(requestId)` immediately after `LP(nonce)` and before the timestamps. Reveal sends exactly this signed ID in `X-Request-Id` and checks the response envelope ID. Invalid or altered grants are rejected before network access; nonce and request ID are consumed locally before the attempt, even on failure. Never retry a grant. Other requests generate fresh IDs. This client does not prove a user session, issue grants or perform auditing. Its local in-memory one-shot check is defense in depth and cannot replace the agent's independent signature/clock/ownership/replay enforcement, including restart and snapshot protections. The agent must enforce all engine binding, ownership and data-sanitization rules; this client cannot attest that it does.

Inspection commands/paths, log events and reveal values may contain secrets. Do not log, persist, cache or automatically resume them. `Logs` invokes its sink synchronously, with a context canceled at teardown and a five-second deadline per event. The sink **must cooperate** with that context and return promptly. The client waits for the sink before `Logs` returns; it cannot force an uncooperative callback to terminate, and therefore an uncooperative sink can block teardown indefinitely. There is no background callback that could deliver bytes after `Logs` returns. After a valid end frame, the client allows five seconds for EOF, rejects trailing frames and still honors caller cancellation; this grace is separate from the stream duration and heartbeat timers. A non-200 response retires the client immediately, while its bounded error body can still be read; caller cancellation, explicit `Close`, and forward loss interrupt that read.
