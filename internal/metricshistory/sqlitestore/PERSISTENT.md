# Unmounted persistent history prototype

`OpenPersistent` is an explicit opt-in API for Linux and macOS; nothing in the product opens it. It uses `history.sqlite3` in an already-existing absolute, clean, private 0700 directory owned by the effective UID. Each ancestor must be root- or effective-UID-owned, non-symlinked, and not group/other writable; writable sticky directories are rejected. No parent directories are created. ACLs are not checked and must be secured by the operator.

The directory, ancestors and local filesystem must remain stable and trusted for the store lifetime. A nonblocking advisory flock on the directory coordinates only cooperating users of this API. Noncooperating same-UID processes, administrators, ACL-authorized actors, hostile filesystems, rollback or path replacement can defeat the checks; SQLite pathname opens are not VFS-anchored. Do not rename or replace the directory while in use. Network or unusual filesystems are not qualified.

Creation is exclusive; an interrupted or failed creation can leave an incomplete file that will not be adopted or automatically removed. Existing databases are admitted immutably and must have the expected identity and exact schema. Any journal, WAL or SHM sidecar causes rejection without automatic recovery. Recovery is an operator decision outside this API. No migrations, retention, deletion, product activation, or capacity bound are provided. Synthetic committed-then-process-exit testing is not power-loss or filesystem ENOSPC qualification. Packaging, runtime filesystem guarantees and operational lifecycle remain gates.
