# Optional Brine metrics history lifecycle candidate

This internal component is not mounted and does not collect metrics. Brine's signed read and ephemeral selected-host view are independent of storage. Startup history is disabled unless an explicit launch setting enables it; a path by itself is rejected. Enabled startup opens only a separately initialized SQLite observation store in a pre-provisioned, trusted, owner-only directory. The SQL format is versioned (`BRMH`, schema 1) and rejects the prototype gauge DB without adopting or overwriting it. `InitializeObservations` is an explicit provisioning API, not called by startup. It does not create the root or repair an interrupted initialization.

A capture stores one bounded atomic sample, Brine's receipt nanos (not the source sample time), and an opaque Brine enrollment incarnation. Missing fields use SQL NULL; measured zero remains zero. A bounded time-range query requires an exact enrollment, returns newest first, and never joins an older enrollment to its replacement. The owner that wires enrollment must generate a fresh, durable, opaque ID per enrollment and revalidate authorization/freshness before append or query. Merely passing a verified-looking struct or an enrollment ID is not proof of authority. No upserts, migration, eviction, refresh backfill, or deletion. Same-enrollment/nanosecond collisions fail without replacing a row.

`Start` owns one store for one running process. Operations take one non-queued admission at a time. `Stop` first closes admissions permanently, then waits for already admitted work, then closes the SQLite handle and releases its root lock. A timed-out wait is not an acknowledgment and doesn't reopen admissions or release the lock early. The caller must persist disable in its launch settings and wait for acknowledged old-process shutdown before restarting off; no hot reload or in-process persistence of settings. On later explicit re-enable the same store is reopened with all acknowledged rows. The mount must not perform SQLite I/O on the response path required to show live values.

Still needed before mounting: durable registry-owned incarnation provisioning and session/ACL-to-enrollment binding; exact launch config and isolated tested startup/shutdown integration; total footprint/cap, operator status and backup/restore policy; driver/release packaging, real fault and restart qualification of this versioned schema; and reviewed signed producer/client/auth before any collection or route. A proof alias or test fake is not a metrics provider. Linux compile is not runtime evidence for these new components. None of these APIs authorizes a live service, a capacity workaround or a history view on an existing host.
