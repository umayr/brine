# Remote agent composition

`Open` validates the entire record, opens exactly its pinned SSH endpoint and socket, and authenticates a fresh agent session against its engine binding on that forward. Success verifies the SSH host key and signed agent/engine binding against the record. It does not verify the reveal-verifier fingerprint, identity of the local key path, or other independently reviewed fields; it is not discovery, trust on first use, enrollment approval, or a user session. No reconnect or fallback is attempted. Close every session; its parent context owns the forward lifetime. Operations use individual caller contexts. Errors retire the session; inventory requires an explicit page bound and returns no partial results on overflow or cursor loops.

The caller must retrieve and recheck the current registry record, including revision and all binding/transport fields, before opening and before delivering results. It must cancel the forward and any active stream when the target changes, is removed, or authorization expires. These checks need synchronization with registry updates at the integration boundary; this package cannot make them atomic. Enforce appropriate timeouts, resource limits, and access control there. The underlying transport requires a trusted private local directory and key, including trusted ancestors and ACLs (see agenttransport documentation).

Reveal is deliberately not implemented: this package has no caller-verified interactive, consented and audited request boundary. Integration must enforce consent, audit and a valid user session before signing, verify the signing key fingerprint against the current record, use fresh one-use nonces and short bounded lifetimes, and record the outcome before delivering values. An authenticated agent session alone does not grant that authority. Never log values or grants.
