# S1: opt-in honest Alpha request history

This is **the existing bounded mutation stream plus authenticated GET lookup**, not asynchronous submission, a queue, a saved-plan executor, reconciliation or new execution authority. Outside explicit `--operation-state-dir`, merged #75 behavior remains unchanged. Legacy is outside this durable profile. This slice does not qualify source execution (#67), complete resource/retention inventory (#66), or actual native app acceptance (#69). **Native app/engine qualification: NOT RUN.** Future actual #69 acceptance must explicitly require this flag and all separately approved source/provider qualification gates; merely writing a record never enables an action.

## Operator-provisioned storage

Use authenticated, configured qualified Alpha (existing explicit Linux Docker socket, independently provisioned expected daemon ID, coordination layout/state and operator-selected compatible Dill candidate). Additionally select `--operation-state-dir /canonical/private/history`. Empty explicit flags reject. No environment variable implicitly enables this profile.

The directory must already exist: canonical absolute, operator-owned mode **0700**, with no access/default ACL and safe root/operator-owned non-writable ancestors. It must be outside editable Brine data **and** Dill coordination state, with neither root nested inside the other in either direction; aliases into editable data reject. Brine does not provision/repair this directory, chmod files, weaken permissions or delete unsafe/corrupt state. Linux descriptor-relative no-follow traversal, retained directory FD, revalidated path/inode, exclusive directory `flock`, owner/type/mode/ACL checks and regular single-link **0600** files protect storage. Another owning Brine server fails startup. This is a local qualified-filesystem contract, not NFS support, an OS sandbox or protection against a malicious same-account writer. Trusted same-account exclusion is required.

Records are atomic bounded closed JSON (`brine.operation/1`), at most 3 MiB each / 4096 records. Writes use an exclusive random mode0600 staging file, file fsync, close, rename and directory fsync. A failed publication can leave private `.pending-*` evidence; startup fails closed rather than cleaning it. The entire root validates before recovery. Unknown names, noncanonical/duplicate/unknown/missing fields, unsafe entries, corruption or ACL changes fail closed. There is no automatic retention deletion or repair API; capacity exhaustion requires explicit operator inspection. No secret-binding/controller state is reused, and this root does not replace or modify Dill coordination locks/journal.

## Ordering and axes

Supported existing lifecycle POSTs (`up`, `down`, `stop`, `start`, `restart`) reserve random `br_<32 lowercase hex>` intent **before Runner or any Dill child, including capability discovery**. Failure to reserve means no launch. The typed per-request `dill.OperationObserver` uses `Started() error` and `Terminal(OperationInvocation) error`, carried with `dill.WithOperationObserver`. `Runner.RequireOperationObserver` fails closed for opt-in mutations without a reserved observer. Read-only plan/validate retain their existing request-scoped semantics; they are not mutation-history submissions. No teardown, delete, secrets, direct SDK or background action becomes allowed.

Accepted/start/observed invocation-end/recovery timestamps are separate. Source binding is explicitly **UNBOUND**: no immutable source digest, evaluator policy, reviewed snapshot or attended source approval is claimed. Optional bounded relative entrypoint is metadata only. Actor is a digest of the existing authenticated account identity, not a token, cookie, CSRF value or browser attribution. It is correlation metadata, not a low-entropy-hash confidentiality/anonymization claim. Configured selector/expected qualified-identity digests remain separate from actual receipt target observations. No raw source, credential URL, host path, process arguments, binary/socket/state path, environment, stdout/stderr or raw diagnostic enters the record/lookup.

Terminal persistence happens **inside Runner before its existing operation-marker writer**. The marker remains exactly `receipt`, `exitCode`, `status`; no history field is added to the producer contract. Invocation status/process exit, receipt outcome/effects and persistence/delivery remain independent. E.g. cleanup exit1 can retain `outcome=succeeded`, `effects=complete`, `status=failed`. Missing/malformed receipt retains nullable Dill ID and unknown engine axes. The random Brine ID is never a made-up Dill `op_...` ID.

History failure after a known receipt suppresses the terminal operation marker (a callback attempt is not a durable commit), returning fixed `OperationHistoryError` and outer stream error, while retaining the original typed invocation in that process's lookup with `persistence=failed_inspect` and `reason=history_failure_requires_inspection`. New submissions fail closed; do not retry. This in-memory observation is **not claimed durable**. If the process subsequently crashes, only actually published valid records survive, otherwise recovery is unknown. Delivery-only persistence failure also cannot erase a known receipt. `OperationDeliveryError` distinguishes opt-in marker transport loss from engine failure without changing the marker schema.

`delivery=not_observed`, `attempted_unconfirmed`, or `write_failed` describes local HTTP observation only. Even successful `Write`/flush or outer `[brine:done]` is **not browser acknowledgement**, receipt delivery, or proof of engine success. Browser disconnect does not cancel existing bounded `context.WithoutCancel` ownership. A child may outlive server death. On restart, accepted/running records without durable terminal become `unknown` / `restart_requires_inspection`, recording recovery time but no invented completion or Dill ID. Valid durable terminal records survive unchanged. No stale PID kill, resume/replay, automatic coordination inspect/ack, reconstructed stdout or inferred rollback occurs.

## API and UI

- Existing authenticated lifecycle POST returns stable **`X-Brine-Request-ID`** and **`Location: /api/operations/{id}`**, flushed before discovery while retaining the existing streaming response. Losing headers before receipt means the browser may not know the request ID; never resubmit automatically.
- **`GET /api/operations/{id}`** is authenticated, no-store, strict opaque ID only, with auth defense even on synthetic/no-auth mounts. There is no list, free-text path, poll, replay, cancel or submission API. Invalid/missing IDs return fixed 404; unsafe history returns fixed 503. Existing cookie CSRF and bearer/session authorization remain unchanged.
- Qualified stack pages show an explicit one-shot lookup input and preserve the Brine ID from response headers independently of stream parsing. Reconnect can paste the saved ID and perform GET only. Text nodes render fixed receipt axes/status; no auto-poll, auto-POST or local credential storage. Lookup exists only when the operator configured S1; otherwise it returns unavailable/not found. Current-stream output alone is still not durable history.

Manual exact Dill coordination inspection plus independent live-resource inspection remains the recovery authority. Opaque receipt/resource digests are not complete inventory. Journal acknowledgement is always separate explicit operator work, never a browser recovery action.
