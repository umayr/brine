# Pinned target registry foundation

`internal/targetregistry` is a standalone persistence and comparison library; it is not wired into local workflows, a UI, SSH, an agent protocol, or engine operations. It does not establish remote trust or certify readiness.

A record contains an operator-chosen stable ID, SSH host, port, user, absolute private-key **path** (not key bytes or a passphrase), canonical OpenSSH host public key, its `SHA256:` fingerprint, agent installation ID and engine ID. IDs are opaque restricted tokens. The public key is a canonical `type base64` entry without options, comment or newline; certificates are not accepted. Validation parses the key and checks that its computed OpenSSH SHA-256 fingerprint matches. Obtain and independently verify both out of band; this package does not perform discovery. Never put credentials or secret material in metadata or paths.

`Open` takes an absolute, clean, private directory. `Add(record, true)` requires explicit operator confirmation and refuses duplicate IDs. `Update(old, next, true)` requires confirmation of the complete new record and compares the entire old record under lock, refusing stale updates or ID changes. **Integration blocker:** `confirmed` is only a caller assertion, not a binding between reviewed bytes and the persisted record, and this API alone cannot prove human consent. A future enrollment integration must implement and test an exact-record approval binding: show the precise complete record (and old and new records for updates), bind affirmative approval to those exact immutable values, and pass only the approved values to this API. Do not wire this API into enrollment until that boundary is designed and verified. There is no automatic enrollment, trust-on-first-use, deletion or retargeting. `List` and `Get` fail on invalid, duplicate, unknown or corrupted stored data; failures must not trigger fallback to another target.

Before future use, a transport must check the actual SSH host public key against the stored public key and fingerprint **during the SSH handshake, before sending credentials or trusting the endpoint**. It must then obtain the installation and engine IDs over that authenticated connection and call `Record.Verify` with all three observed values. Missing or mismatched values fail. This comparison alone does not authenticate observations, prevent substitution by a compromised host, bind a later connection, provide endpoint availability, or authorize an operation. The caller must bind verification to the same connection and re-check any identity changes, and must treat unavailable identity as failure. Never retry using ambient local defaults.

Storage uses a versioned strict JSON envelope, private permissions, a cooperating-process advisory lock, same-directory atomic rename, file sync and directory sync. A sync error after rename has an uncertain commit outcome: re-read before retrying, and never interpret the error as proof no change occurred. Existing malformed storage is not overwritten. The directory and its ancestors must be trusted against modification by other users/processes; advisory locking does not protect against non-cooperating writers. Use a local filesystem with working lock, rename and sync semantics. This Unix implementation does not claim portability to Windows or resilience against a malicious process with access to the registry directory. No migration or backup recovery is implemented.
