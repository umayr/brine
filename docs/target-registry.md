# Pinned target enrollment

`internal/targetregistry` stores complete reviewed SSH, agent, engine and reveal-verifier identity bindings. With remote access explicitly enabled, Brine provides an authenticated enrollment UI that displays the complete candidate and, for updates, the previous record; binds approval to those immutable values in a one-shot review; and re-observes the endpoint before committing. The registry itself does not establish remote trust or prove human consent. See [`internal/targetregistry/README.md`](../internal/targetregistry/README.md) for the record, comparison and storage contracts.

Provision the agent and obtain its identities independently before entering a record. [Dill's proposed manual provisioning guide at the reviewed revision](https://github.com/umayr/dill/blob/5e493fdaf1b32363b4b3d620b1422be77725d280/docs/host-agent-install.md) describes its installation identity, engine identity, socket and SSH prerequisites. This guide and the SSH transport remain **unqualified by a real-SSH test**. Same-UID SSH access may expose other sockets; engine access can be host-privileged. Do not interpret the agent as an operating-system security boundary.

For enrollment, independently obtain and verify the SSH host, port, user, private-key path and canonical host public key and fingerprint; the agent installation public key, installation ID and fingerprint; engine ID, kind, socket, daemon ID and generation; the agent's remote Unix-socket path; and the reveal-verifier fingerprint. The exact formats are specified in the [registry README](../internal/targetregistry/README.md). The key path names a Brine-host file and is not itself attested; the reveal-verifier fingerprint is checked against the locally configured signer when a reveal is requested, not proven during initial observation. Verify the SSH host key before credentials and the agent and engine identity on the owned connection. Missing, changed or unavailable identity fails closed; never fall back to ambient local defaults.

The registry assumes trusted private storage and ancestors, cooperating writers, and a filesystem with working locking, rename and sync semantics. An error after publication can leave an uncertain outcome; inspect before retrying. These controls are not hardware attestation and do not protect against a compromised host or an untrusted process with access to the private directory.
