# Pinned target registry foundation

`internal/targetregistry` stores complete reviewed SSH, agent, engine and reveal-verifier identity bindings. It is a standalone persistence library; it does not establish remote trust, provide an enrollment UI, or authorize access. See [`internal/targetregistry/README.md`](../internal/targetregistry/README.md) for its current record, comparison and storage contracts.

An enrollment integration must display the complete candidate and, for updates, the previous record; bind affirmative approval to those exact immutable values in a fresh, authenticated, one-shot review; and re-observe the endpoint before committing. The registry's value comparisons and compare-and-swap do **not** prove human consent. Verify host keys during the SSH handshake before credentials, verify agent and engine identity on the same owned connection, and compare the actual reveal verification key with its enrolled fingerprint. Missing, changed or unavailable identity fails closed; never fall back to ambient local defaults.

The registry assumes trusted private storage and ancestors, cooperating writers, and a filesystem with working locking, rename and sync semantics. An error after publication can leave an uncertain outcome; inspect before retrying. These controls are not hardware attestation and do not protect against a compromised host or an untrusted process with access to the private directory.
