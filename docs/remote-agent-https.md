# Direct remote agent: first transport slice

Dill can generate and export pairing material locally. Brine's Remote hosts page pairs from that bundle and uses the same private registry and read lease as the SSH path. Direct HTTPS requires no SSH forwarding directory. Forgetting a target in Brine does not invalidate copies of the host token.

- One direct private IP and port per host; no proxy or redirect following. The initial transport accepts RFC 1918, IPv6 unique-local and loopback literals. It does not expose a Docker TCP endpoint.
- Dill serves TLS 1.3 with an operator-provisioned certificate/key and requires a per-agent bearer credential on every supported request. Brine checks the independently supplied SHA-256 pin of the leaf certificate DER and the certificate validity period before sending that credential. The token is the unpadded base64url encoding of 32 random bytes. Keep the token, private key and their directory paths private. Replacing the pinned certificate requires enrolling the new pin; changing the token requires updating both ends and restarting the agent. There is no online discovery or trust on first use.
- The HTTPS allowlist is `/v1/session`, `/v1/inventory`, `/v1/inspect`, and `/v1/logs`. The read protocol still verifies the enrolled signed agent and engine binding. HTTPS reveal, uploads and all deploy/remove paths are excluded from this slice.

Dill's `init-https` generates stable credentials and `--print-https-pairing` explicitly exports a reusable secret bundle. `DILL_AGENT_HTTPS_BIN=/absolute/dill-agent go test ./internal/agentclient -run '^TestHTTPS'` covers the built Dill process and Brine client over loopback against a synthetic Docker Unix socket, including optional catalogue-backed upload and manifest lookup. The Brine handler test separately covers operator pairing, inventory and forgetting. These are not real-host deployment evidence.

From **Remote hosts**, select **Deploy a project** on an HTTPS target. Enter a Brine project name, review the captured file list, and confirm transfer. Brine verifies the returned manifest against the captured bytes before requesting Dill’s named preview. Effective Brine variables are not transferred. Only trusted projects may be evaluated; staging and preview do not grant write authority.

If Dill has explicitly enabled checked creation and the preview shows no existing resources, Brine shows a separate **Create stack** confirmation and a request status link. Save the link before confirming if you might disconnect. An unconfirmed response is not retried; open the same link to observe recorded status. The current slice creates new Docker stacks only. Updates, managed removal and remote Git auto-deploy are not enabled.

 The combined Dill entrypoint can also be tested by pointing `DILL_AGENT_HTTPS_BIN` at the built `dill` binary and setting `DILL_AGENT_HTTPS_SUBCOMMAND=1`. Add deployment separately behind a host-local setting, with snapshot review, target-local preflight and shared CLI locking, durable outcome lookup, and managed-only removal that retains data. Brine, never the agent, watches Git and submits exact-commit snapshots through the same deployment path. Unknown write outcomes are not retried.
