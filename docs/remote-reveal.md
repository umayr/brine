# Optional remote environment reveal

Remote reveal is OFF by default. Remote read does not require reveal state. To enable it, configure authenticated remote access and all three flags: `--remote-reveal-enabled`, `--remote-reveal-seed-path /absolute/path/to/seed`, and `--remote-reveal-audit-dir /absolute/path/to/audit`. Startup fails closed if the configuration or existing key or audit is unusable. No key is generated and startup never initializes or repairs the audit. The seed must be independently provisioned as 64 lowercase hex characters representing 32 Ed25519 seed bytes (optional final LF); independently verify that its public-key fingerprint matches the enrolled agent's reveal verifier. Protect the seed as a sensitive signing credential.

Initialize the audit **separately**, before enabling the server, in an existing empty private 0700 directory: `brine-reveal-audit-init /absolute/path/to/audit`. This command does not start Brine. Do not repeat initialization after an uncertain result or lost state without stopping writers and reconciling it; use an external inventory/anchor to detect loss of the whole root. Audit and key ancestors, filesystem, ACLs, and all same-UID processes must be trusted. Mode checks do not establish safe ACLs. Root or same-UID attackers can read or replace state or key and bypass these protections. Use a local filesystem with reliable locking, append, fsync and close; see `internal/revealaudit/audit.go` and `internal/revealsigner/README.md` for the full assumptions.

Review and approval bind the exact target record and full container ID to a single cookie session. The durable journal contains identifiers, not values. A crash, cancellation, I/O failure or uncertain sync can leave pending or ambiguous intent/outcome: stop and reconcile, do not automatically retry or infer delivery. A successful audit outcome means a validated reveal was obtained, not that the browser received it. Reveal requests have a 30-second request timeout and response write deadline, including final HTTP framing and error responses. Cancellation cannot interrupt a blocked operating-system filesystem call. Logout/shutdown cancel work on a best-effort basis but cannot recall requests or bytes already sent or buffered; revocation and delivery are not atomic. Browser clearing is best effort: sleep, suspension, throttled timers, networking and buffered bytes prevent immediate clearing or guaranteed erasure. Metadata and logs can also contain secrets.

Docker socket access is effectively host-privileged; use an isolated target and protect agent access accordingly. Real SSH transport is not qualified by synthetic tests; validate the deployment and pins independently. See `internal/remotereveal/README.md` for executor and audit limitations.
