# Stack source history

**Restore writes files, not runtime state.** Open **History → Checkpoint** to retain the saved Pkl project. The review lists the entrypoint, files and sizes. Only **Retain source revision** captures bytes. To restore, choose **Restore** on the stack, select a retained revision, review the file changes (optionally show the line-by-line source diff), then **Restore as new revision**. Unchanged source cannot create another checkpoint. Reviews are bound to the stack, saved files, revision history and browser session and expire after five minutes.

For example, retain r1, then edit the source. Restoring r1 first preserves the edited files as r2 and then writes r3 ← r1. Nothing is deployed. Inspect Compose and run a new Plan if you intend to change live resources separately. History's remote request references are evidence under a stack name, not a health check, backup, or guarantee of success. A receipt cannot be restored. **View diff** compares each retained revision to the preceding retained revision, without granting restore authority. Over-limit or non-text files are listed with an explicit explanation instead of a partial inline diff.

**Auto-Checkpoint** defaults off. **Settings → Source History** controls the default for all eligible local stacks. Changing the global setting does not scan or copy existing source; it applies from the next eligible browser save. In a stack’s History, choose **Enable Auto-Checkpoint** to retain a baseline and turn it on for that stack, **Disable Auto-Checkpoint** to opt out, or **Use global default** to inherit again. Stack overrides take precedence, including after the global default changes. After authenticated browser source saves Brine retains new file content and entrypoint changes, not duplicate content. If retention fails, the edit remains saved and Brine warns that no checkpoint was retained. API clients using only a bearer token cannot authorize archive writes; saved source edits on an enabled stack return `X-Brine-Source-Checkpoint: not-retained`. External file writes, Git pulls, runtime actions, variables and secret stores are not captured. No setting reconstructs earlier unretained edits.

## Opt in offline (Linux only)

By default no archive is opened and nothing is retained. No change to an existing installation is required. There is no automatic capture, online key management or automatic pruning. Only enable this for a **single authenticated local manager** with exclusive ownership of its data and archive, backed by a reliable local filesystem. No remote/staging worker, shared writers, Git checkout or previously secret-managed project is eligible. Engine ownership inspection is read-only and must succeed at review and confirmation.

1. Back up Brine data. Independently verify the local manager's protection and recovery state. The private `<data-dir>/secret-state` directory must be present and trustworthy. **Never recreate a missing protection directory to make a used installation eligible.** For a verified fresh data directory only, provision an empty mode-0700 protection directory before first use. Preserve it on backup and recovery. Any existing protection entry for the deployment blocks retention.
2. Separately provision an **empty mode-0700 archive** and a **32 raw byte key** in a single-link mode-0600 file under a separate mode-0700 key directory. Brine never generates the key. Use canonical, absolute, symlink-free paths outside the data directory and outside each other. Use the service UID, trusted ancestors without group/world write or extended/default ACLs, and a backup strategy for the archive, data and key. In containers, keep these mounts persistent at the same paths; mount the key read-only. Do not put the key or retained data in Git.
3. Against those pre-existing paths, run Brine once with `--init-source-history --data-dir <data> --source-history-dir <archive> --source-history-key <key-file>`. Initialization refuses a nonempty archive; startup never initializes one. Start the service with the same paths, without the init flag, with a local engine socket and authentication enabled. A missing or wrong key, identity mismatch or damaged archive is an error, not permission to initialize again.
4. In a signed-in browser open the stack's History. There is no bearer-token write path. Source is limited to private, service-owned mode-0700 directories and single-link mode-0600 project files: up to 128 `.pkl` files or a root `PklProject`, 4 MiB total. Extra entries (including hidden files), links, nested mount points and empty subdirectories are refused, not silently discarded. Requires Linux `openat2` and atomic directory exchange. Project bytes can themselves contain sensitive data: encryption at rest does not redact content, and the administrator can reveal it during comparison.

The encrypted archive defaults to 100 objects and 256 MiB of logical sealed bytes across all stacks, including unpublished remnants. Set `--source-history-max-objects` (1–512) and/or `--source-history-max-bytes` (1–536870912) on the server command and restart; zero or omission uses the default. For example, append `--source-history-max-objects 200 --source-history-max-bytes 314572800` to your existing startup arguments. Do not reinitialize the archive or change the key. Lowering either limit leaves existing history readable, even above the new limit, but blocks writes that would exceed it. A restore can need two slots: one for current uncheckpointed edits and one for the restored revision. History shows current usage; confirmation checks capacity again before publication. The byte setting is not a filesystem quota. Startup and writes authenticate the retained archive; larger archives take more work. The per-project source limits above are unchanged. A build with the old fixed limits cannot open a larger archive or read a stack lineage longer than 100; preserve a matching backup before upgrading if you need to downgrade. Each stack can reach only its own registration's revisions. Recreating a deleted stack with the same name does not revive the old history. Retention includes source files and entrypoint, not Git state, deployment receipts, Docker resources, databases, volumes, configuration variables, secret stores or executable permission bits.

## Interrupted publication or loss

If confirmation is lost, reload History and inspect the actual source before making another change. **Do not replay an unknown write.** The workspace is exchanged with a private sibling directory. If `stacks/.source-restore-<name>` remains, Brine fences that stack even when history is disabled. Stop all writers, preserve both directories, archive and key, and recover from a verified consistent offline backup. Never delete a marker or initialize an empty replacement as a shortcut. Orphaned encrypted objects consume capacity but grant no restore authority; there is no supported online GC. Preserve matching workspace metadata and archive contents together; key or archive loss is not recoverable from a request record.
