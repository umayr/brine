# Named preflight consumer: pure, inactive seam

This change implements only the frozen revision-4 `dill.preflight/1` public codec and structural argument/binding helpers. **It does not enable execution.** No Runner method, subprocess, HTTP endpoint, UI review, history-v2, activation flag, source capture, existing operation parser, provider code or candidate pin is changed.

The byte-exact 15-file synthetic fixture corpus and its contract/corpus hashes are recorded in `internal/dill/testdata/preflight-v1/PROVENANCE.md`. These are design vectors, not actual b3 runtime capabilities. Accepted b3 pins remain unchanged; a future candidate without the separate preflight capability must fail without fallback. Existing operation/1 discovery remains separate, and `DecodeOperationInvocation` still rejects `PREFLIGHT_MISMATCH` and the other new negotiated code. Actual bound-operation decoder negotiation belongs in a later change.

## Pure APIs

- `DecodePreflightCapabilities`: exact supported object or exact two-field unsupported object. Static support is not target readiness, native placement, source proof or permission.
- `DecodePreflightResult`: exact 14-key envelope; recursively closed required non-null objects/arrays/scalars except required nullable target/inputDigest/selectionDigest. Rejects missing, duplicate, unknown, mistyped, non-integer, unsafe-name, contradictory identity/action, incomplete and oversized evidence. Accepts one UTF-8 JSON object with optional one terminal LF, no leading/trailing whitespace or other frame; interior JSON whitespace is allowed. All bytes including the LF count toward 262144. Display names/identities must be literal safe ASCII, not escaping-expanded. Names are at most 255 bytes; at most 256 unique `(kind,name)` rows.
- `ObservePreflightInvocation`: combines stdout with an **independently supplied** process exit. Missing/invalid exit, malformed evidence or outcome/exit mismatch yields `unknown` with nil result, never a normalized success. It retains the independently reported exit separately; successful review requires exit 0. Unknown metadata remains unknown even when engine effects are proven `none`.
- `DecodePreflightInvocation`: strictly decodes the local `{result,processExit,status}` DTO. A nil result is only valid with status unknown. A non-null result must pass the same result/exit coherence rules. This API validates shape, not subprocess provenance or browser marker trust.
- `CheckPreflightBinding`: requires a complete successful invocation and exact independently trusted stack, one of five actions, Docker, selector endpoint digest and known qualified identity digest. Revalidates mutable DTOs. A supplied or learned-from-selected-socket expected identity is not independently trusted. This function is **not** confirmation authority.
- `BuildPreflightArguments` / `BuildBoundPreflightArguments`: construct canonical grammar for full-stack up/start/restart/stop/down. Explicit config (`-f`), Docker/socket/stack, all four coordination fields, fixed source `brine`, timeout `5m`; Up uses `--no-prune --pull never`. Bound apply uses both suffix flags and the already-prefixed selection hash verbatim. No source digest provider flag exists.
- `ValidatePreflightArguments`: checks only that closed Brine structural profile. Allows Go flag single/double dash, string equals/separate values, stack aliases and quiet; rejects duplicate semantic fields even if equal, operands/bare separator, unknown or forbidden flags even when false, partial binding, and Up-only flags on other actions. Boolean flags use Go bare/equals syntax. Explicit timeout must be positive. Unlike the broader provider grammar, this Brine profile requires source brine and Up no-prune=true/pull=never. Values are not scanned for substrings that resemble flags.

All rejection errors use fixed safe text, never SDK/Pkl/JSON diagnostics, property names, paths, user names or payload sentinels. Preview errors use exactly the frozen 17-code/message vocabulary, maximum four entries: one primary stage error, then close/commit/release in that order. Successful evidence requires written coordination, engine none, valid opaque digests, no errors, complete scope counts/present counts matching unique rows, and exactly one network. Every failure has empty rows, null digests and zero/false coverage; truncation is tied only to the limit error. Cleanup overrides outcome to unknown, never approval.

## Meaning and limits of evidence

The row relation distinguishes present raw lowercase 64-hex container/network IDs, present engine-name volume identity, and absent planned-name namespace references. **Planned-name is not a create promise.** Recreate displays the old inspected ID; the replacement's future ID is unknown. A parser can reject short/prefixed/name-fallback/contradictory IDs, but cannot distinguish two syntactically valid 64-hex IDs or prove inspection/name consistency. No local SDK corroboration or reselection is introduced to rescue evidence.

The provider must prove actual old IDs, authoritative matching names, ownership/local-driver/options and private live safety facts under retained qualification. Volume ensure iff a captured create/recreate consumes it also needs provider-private capture facts: the consumer can reject ensure without any create/recreate, but cannot reconstruct mount membership from public rows. Volume engine-name is not immutable incarnation/content identity. No-delete retention is not backup; same-name volume replacement/content changes are not guaranteed detectable. Container removal/recreation loses its writable layer.

`ensure-started` may call start: config-noop does not promise zero engine writes. The projection is a possible-attempt/resource superset, not an executable ordered plan or transaction. Empty start/restart may ensure an absent network with zero container rows; absent stop/down rows mean none. Neither preview success nor its rows predict apply success. Existing b3 Down semantics stay unchanged: it retains the network and normally fails partial/none with an inspection barrier if that network exists. Existing cleanup may remove only newly created IDs. External callers/races remain possible after comparison.

Input and selection digests are opaque consumer commitments, not authentication or secret declassification. The consumer does not recompute provider-private HMAC/store/live/config facts. Test-only canonical recomputation uses only the synthetic private key and supplied desired-config hash leaf, preserving that original desired-image provenance separately from prepared image ID, dependency set and flags. No actual environment/source/Settings/path/secret artifact is exported. Runtime running/health state and SourceSnapshotDigest are not committed by this provider contract; source proof stays Brine-owned and private.
